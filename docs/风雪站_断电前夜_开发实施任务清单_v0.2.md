## 1. 版本定位

v0.2 把 v0.1 的"可玩灰盒"推进为"可对外展示的成品级垂直切片"。规则层零改动；UI、场景、角色、音频、演出全部重做；允许新增只读规则状态的演出型内容（开场、危机、结局）。v0.2 同时为外部真人盲测做准备（补 QA_REPORT_v0.1 留下的输入缺口）。

## 2. 成功标准（可验证）

1. 17 项 Python 规则回归 + 6 项 UE 自动化测试 + 三路线 `-WhiteoutAutoRoute` 全程绿（规则零改动的证据）。
2. 实机截图基线：五个站区、HUD、证据板、结算页、开场演出全部重制，存入 `docs/baseline_v0.2/`。
3. 玩家可见文本全中文；不出现任何枚举名或内部 ID（如 `EWSReasonCode`、`FACT_*`）。
4. 每个付费行动执行前显示预览确认；每次拒绝给出人话原因与至少一个可改变条件（设计文档 §11.2、§11.3）。
5. 新玩家开场 2 分钟内理解首要目标与行动点含义（设计文档 §14.1）。
6. Win64 Shipping 包归档至 `Builds/WhiteoutStation-v0.2-Win64` 并通过独立烟测。

## 3. 设计铁律

1. **规则零改动**：不改任何行动成本、前置条件、状态差值、评分权重与结局判定；`WhiteoutStationRules.v0.1.json` 与 `Tools/Rules` 测试冻结。任何意外触碰都会被 G5-01 回归守护拦下。
2. **表现层只读**：UI、美术、演出只读取 `WindStationStateSubsystem` 快照与事件委托；所有状态变化仍走统一的行动预览/提交管线，UI 不得直接改权威状态。
3. **行动点不是菜单税**：查看新 UI（证据板、对话菜单、结算复盘）一律免费；演出型内容 AP 成本必须为 0。
4. **确定性不破**：演出不改变结算结果；模型调用预算、降级链与事实白名单维持 v0.1 行为。
5. **等级化显示**：人物状态只显示等级（稳定/紧张/危险/危重等），不暴露精确数值（设计文档 §6.1）。
6. **资产可审计**：所有第三方资产经 `Tools/Assets` 管线入库并记录于 `SourceAssets/ASSET_LICENSES.md`（来源、作者、许可、校验值）。

## 4. 优先级与变更规则

- **M0**：阻塞"完整闭环体验"的表现任务。缺失时 v0.2 不成立。
- **M1**：完整体验所需。缺失时 v0.2 可展示但不完整。
- **M2**：锦上添花。时间不足时优先删除，不影响验收。
- **变更准入（沿用四问）**：新增任务必须说明——它改变哪类玩家决策？占用多少行动点（演出类必须为 0）？与哪些状态交互？是否增加模型调用？答不上来不进清单。
- **依赖顺序**：G0（W2-01~03 样板间）→ W1 与 W2 剩余并行 → W3 → W4 → G5。W1-04 与 W4-01 为一体设计，同步实施。
