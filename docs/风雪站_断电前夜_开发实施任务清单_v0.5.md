# 风雪站：断电前夜 — 开发实施任务清单 v0.5

日期：2026-07-25

依据：v0.4 发布版、当前源码与规则审计、DeepSeek V4 官方 API 文档、Unreal Engine 5.8 HTTP/Retry API、三条既有路线与线上 API 实测。

## 一、版本目标

v0.5 完成“受控 AI 表达 + 可验证玩法选择”的闭环：

1. C++ 规则状态仍是唯一权威；模型只生成 NPC 台词表达，不能修改 AP、资源、事实、任务、关系或结局。
2. DeepSeek `deepseek-v4-flash` 采用非思考模式和严格 JSON 响应；任何网络、协议、schema 或事实校验失败都返回确定性本地台词。
3. 玩家选定的询问、质疑、安抚、承诺及承诺条件以结构化字段进入本地决策与模型上下文。
4. 口粮分配与治疗资源不再由交互点硬编码，玩家可在行动预览中切换合法方案。
5. 顾衡和叶澄的人物模型、骨骼、材质、动作、动画、AnimBP、LookAt 表现全部冻结。

## 二、设计与安全铁律

- **规则权威**：模型返回值只允许 `npc_line`、`emotion`、`used_action_id`、`referenced_fact_ids`；提交状态只能走 `FWhiteoutRulesEngine::Commit`。
- **显式意图**：正常游戏不调用在线意图分类。玩家点击的意图即规则意图，模型无权重解释或改写。
- **凭据隔离**：`WHITEOUT_LLM_API_KEY` 只发送给 HTTPS 且主机严格等于 `api.deepseek.com` 的官方端点；loopback mock 永不携带该 Header；其他端点拒绝启用。
- **确定性降级**：模型关闭、无密钥、超时、429/5xx、空正文、截断、内容过滤、schema 失败或事实越界时，UI 必须在有限时间显示本地回应。
- **隐私审计**：入库证据与默认运行日志不保存 API Key、Authorization、system prompt、玩家原文或完整模型回复。
- **角色冻结**：禁止修改：
  - `WhiteoutStation/Content/WindStation/Art/Characters/**`
  - `SourceAssets/MakeHuman/Characters/**`
  - 两名 NPC 的 SkeletalMesh、Skeleton、Animation、AnimBP、材质、动作和 LookAt 表现代码
- **用户改动保护**：工作树中的 `MVP_StationMap.umap` LFS 修改视为用户关卡编辑，不纳入 v0.5 源码提交，不执行 stash/reset/checkout/clean。

## 三、技术依据

- DeepSeek V4 默认启用 thinking；短输出会把 token 消耗在推理内容中。v0.5 对实时 NPC 表达显式设置 `thinking.type=disabled` 和 `stream=false`。
- DeepSeek JSON Output 要求请求包含 JSON 指令并设置 `response_format=json_object`；正文仍需由客户端严格校验。
- UE 5.8 提供 `FHttpRetrySystem`、错误原因与退避支持；只对连接失败、429、500、503 做一次有上限重试。
- 研究中的 bounded autonomy 与参数化动作经验用于本版边界：离散意图和结构化参数进入确定性规则，LLM 只消费规则投影并生成可丢弃的表达。

## 六、实现要求

### V5-01 v0.5 版本资源与角色冻结基线

- 规则与 Agent runtime 文件升级到 v0.5 命名，`rules_version`/schema 和加载路径一致。
- 存档槽升级，禁止旧规则存档静默混入新局。
- 记录受保护目录在基线提交的 Git tree OID；最终门禁重算。
- 当前用户地图 LFS OID 单独记录为工作树状态，不纳入版本源树。

### V5-02 DeepSeek V4 请求与端点安全

- 表达与保留的意图探针均发送：
  - `thinking: {"type":"disabled"}`
  - `stream: false`
  - `response_format: {"type":"json_object"}`
- 官方认证端点必须经 URL 解析后满足 scheme=`https`、host=`api.deepseek.com`。
- loopback 仅允许 `127.0.0.1`、`localhost`、`::1`；不得附加 DeepSeek Key。
- 未知远程端点或近似域名拒绝成为 live provider。

### V5-03 HTTP、schema、审计与生命周期

- 只对连接失败、429、500、503 重试一次；总超时有限。
- 只接受 OpenAI Chat Completions envelope、`finish_reason=stop`、非空且不超过 64 KiB 的 content。
- 400/401/402/422、length、content_filter、insufficient_system_resource、空正文分别给稳定原因码。
- 表达 JSON 只允许四个必填字段；未知字段、缺失事实数组、超长/空 emotion、事实越界均拒绝。
- 审计记录 request id、动作、意图、模型、HTTP/finish、耗时、token 数、字节数、结果；不记录原始请求/响应文本；文件达到 2 MiB 后轮转。
- 网关持有活动请求；新局、读档、销毁时取消并提升 generation，旧回调不得写入新会话。
- 模型调用预算只由规则状态子系统决定；网络重试次数另作传输指标。

### V5-04 结构化上下文与 AI 状态

- 删除按 ActionId 全局排队玩家文本的旁路。
- 同一次 `FWSActionRequest` 的 `DialogueAct`、`PromiseCondition` 与最多 280 字玩家文本直接传至表达请求。
- 请求上下文包含 speaker/action/response_type/emotion/preset、dialogue_act、promise_condition、player_said、允许事实和只读 AP。
- HUD 回应区显示“DeepSeek 在线表达 / 本地预设 / 在线失败后本地降级”；不得显示内部 prompt、Key 或完整错误载荷。
- 非对话行动不发模型请求，不再浪费不可见调用。

### V5-05 对话意图与承诺一致

- `Ask` 保持既有信息推进。
- `Challenge`、`Reassure` 对压力/信任产生确定且可测试的不同修正；事实披露仍受证据白名单约束。
- `Promise` 只允许顾衡和三个白名单条件；叶澄的承诺按钮禁用且规则层也拒绝直接构造的请求。
- `FWSActionResult` 与事件日志记录 dialogue act / promise condition，复盘可追踪。
- 本地预设台词按显式意图和承诺条件变化；在线模型只能改写该确定性决定。

### V5-06 资源方案选择

- 行动预览保存完整 `FWSActionRequest`，第二次 F 按当前请求提交。
- Q 在预览中循环：
  - 口粮：玩家、顾衡、叶澄的全部非空且总量不超过 2 的组合；
  - 治疗：药品 / 已发现的保温包。
- 预览实时显示所选对象、数量、资源、可执行原因；无效方案仍可查看但不能提交。
- 规则层已有参数校验继续作为最终边界，UI 不替代规则验证。

### V5-07 状态与评分一致

- HUD 五条统一为“健 / 温 / 精 / 饱 / 稳”，全部以越高越好显示；压力条使用 `1-pressure`。
- `Fatigue` 在本版继续保留存档字段名，但展示与评分语义明确为“精力”；`Hunger` 明确为“饱腹”。
- Python 评级按降序下限判定，与 C++ 的 `>=90/80/70/60` 一致，覆盖 59.x、69.x、79.x、89.x。
- 三条黄金路线的参数在 JSON、Python、C++ AutoRoute 中一致。

### V5-08 自动化

- Python 增加资源选择、叶澄承诺拒绝、意图差异、浮点评级、随机合法路线不变量。
- UE 增加玩法选择/对话上下文、严格 envelope/schema、端点安全、会话 generation 测试。
- contract mock 至少支持：valid、empty、length、content_filter、malformed、extra_field、401、429→200、500、503、delay。
- 自动断言：回调有限、fallback 非空、模型前后规则状态一致、loopback 无 Authorization、预算不超过 10。

### V5-09 在线与发布

- 桌面 Key 仅由外部测试进程读取并注入环境变量；不得复制进仓库、本地命令行参数、日志或证据。
- 线上测试至少验证：
  - HTTP 2xx；
  - 返回模型与 `deepseek-v4-flash` 兼容；
  - `finish_reason=stop`；
  - 正文严格 JSON 且通过项目 validator；
  - thinking token 为 0 或请求明确处于 disabled；
  - 顾衡与叶澄至少各一条表达成功。
- 发布构建来自 detached clean worktree，输出目录唯一；manifest 记录 source commit/tree、UE/Python 版本、阶段时间与关键文件 SHA-256。
- Shipping 覆盖显式关闭、启用但无 Key、端点失联三类降级和三条成功路线。

### V5-10 文档与提交

- 产出 `PROGRESS_v0.5.md`、`QA_REPORT_v0.5.md`、`BUILD_AND_PLAY_v0.5.md`、`RELEASE_MANIFEST_v0.5.md`、各 Gate 记录和 `Distribution/README_v0.5.txt`。
- 每个阶段只暂存明确文件；禁止 `git add -A`。
- 提交前运行历史凭据扫描和角色资产保护检查；完成后推送当前分支。

## 七、完成定义

以下条件全部成立才算 v0.5 Demo 完成：

1. V5-01 至 V5-10 全部 PASS；
2. Python 与 UE 自动化没有失败、警告、未运行或陈旧报告；
3. DeepSeek 真实表达至少两条 accepted，故障路径全部确定性降级；
4. 三条黄金路线与新增选择在最终 Shipping 包可运行；
5. 角色保护目录 tree OID 与基线一致；
6. 发布包和证据绑定当前提交，凭据扫描无命中；
7. 用户地图改动保持原状且未被纳入提交；
8. 版本文件、文档、提交和远端推送完成。
