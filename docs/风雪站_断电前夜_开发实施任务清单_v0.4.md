## 一、v0.4 范围决策

1. **规则继续零改动**：`Content/Rules`、`Tools/Rules`、`Source/*/State` 冻结，`RULE_FREEZE` 哈希、17 项 Python、6 项 UE 自动化继续执行。所有改动只发生在表现层（HUD/输入/材质/贴图/文案）。
2. **用户已拍板两项**（不再讨论）：
   - 对话界面右侧 NPC 大卡内的肖像**移除**（连带 HUD 右栏两张 NPC 卡的肖像也移除，反馈原文"人物信息中展示的NPC的图片应该移除"）；
   - 叶澄的德国红十字（DEUTSCHES ROTES KREUZ）救援夹克贴图**更换**。
3. **UI 目标形态的唯一标准** = v0.2 反馈文字 + 5 张参考图 + `UI_STYLE_v0.3.md` token 表。即：低遮挡模块化局部黑色毛玻璃；墨刷底板只用于准心提示/交互信息/通知；橙色只用于 AP/警告/当前交互目标；可交互物细白描边。优先级：**v0.3 反馈文字 > v0.2 参考图 > 既有 token**。冲突示例：v0.2 的 Q 轮盘图仅作按钮风格参考，对话流程一律按 v0.3 反馈的原神式流程。
4. **ESC 铁律**：ESC 在一切面板/状态下都是"返回上一层"，最深层返回游戏。任何面板不得出现"只能点鼠标关闭"的情况。
5. **模型红线不变**：固定 `deepseek-v4-flash`；模型只做表达改写，不改状态/规则/AP/资源；密钥只经环境变量 `WHITEOUT_LLM_API_KEY` 或不入库的 `LocalConfig/WhiteoutLLM.ini` 注入；每次提交前 `git grep` 扫描；AutoRoute 全程不依赖模型。

## 三、执行原则

1. **照抄原则（针对视觉任务，最重要）**：每个 UI 任务已指定"对照哪张参考图 + 用哪些 token 值 + 布局数值"。执行 Agent **禁止自由发挥、禁止发明新样式、禁止"差不多就行"**。验收方式就是截图与参考图并排对比。
2. **代码锚点原则**：每个任务写明改哪个文件哪个函数（附行号）。先读锚点处代码再动手，不得在无关文件里新建平行实现。
3. **规则红线**：任何任务不得触碰规则 JSON、Python 规则层、C++ State 目录。对话文案、开场白全部走表现层字符串表，不进事件日志、不改结算。
4. **不假按钮**：无功能入口如实禁用；交互状态必须有视觉反馈。
5. **密钥禁令**：见 §一.5。反馈 docx 中的密钥字符串永不复制进任何代码/文档/提交。
6. **降级链完整**：模型不可用/预算耗尽/校验失败时，一律回退确定性预设台词，UI 不得卡死或空白。
7. 完成每个门禁后跑该门禁验收命令，截图存 `docs/baseline_v0.4/` 对应子目录。

### V4-01 全局 ESC 返回与 UI 导航状态机（M0，G0）

**目标**：ESC 在任何面板/状态下都执行"返回上一层"；证据板打开时释放鼠标；不再有面板叠加。

**根因定位（先读再改）**：
- `Private/HUD/WhiteoutHUDWidget.cpp:1877` 与 `:1916`：打开暂停/设置时切 `FInputModeUIOnly`，键盘事件全被 Slate 吃掉，`Private/Player/WhiteoutCharacter.cpp:171` 的游戏侧 ESC 绑定再也收不到 → 所以 ESC 关不掉菜单。
- `WhiteoutHUDWidget.cpp:1395` `ToggleEvidence()`：只翻转 `bEvidenceVisible`，从不碰输入模式与鼠标 → 所以证据板没有光标。

**动手步骤**：
1. 在 `Public/HUD/WhiteoutHUDWidget.h` 私有区新增：
   ```cpp
   enum class EWSUILayer : uint8 { Game, Preview, Evidence, Dialogue, Pause, Settings, Results };
   EWSUILayer CurrentLayer = EWSUILayer::Game;
   void SetLayer(EWSUILayer Layer);
   void HandleBackRequested();          // ESC 统一入口
   void CloseEvidence();                // 关证据板并恢复游戏输入
   virtual FReply NativeOnKeyDown(const FGeometry& InGeometry, const FKeyEvent& InKeyEvent) override;
   ```
2. `NativeOnKeyDown` 实现：若 `InKeyEvent.GetKey() == EKeys::Escape` → 调 `HandleBackRequested()` 并 `return FReply::Handled()`；若 `== EKeys::E && CurrentLayer == EWSUILayer::Evidence` → 调 `CloseEvidence()` 并 Handled；其余 `return Super::NativeOnKeyDown(...)`。（UIOnly 模式下键盘只到 widget，这一层兜底是 ESC/E 能用的关键。）
3. `HandleBackRequested()` 按下表路由（把这张表原样写进代码注释）：

   | 当前层 | ESC 行为 |
   |---|---|
   | Settings | `CloseSettings()`（回到 Pause） |
   | Pause | `ResumeGame()` |
   | Evidence | `CloseEvidence()` |
   | Dialogue | `CancelDialogue()`（走 `AWhiteoutCharacter::CancelDialogue`） |
   | Preview | `HideActionPreview()` |
   | Results | 打开暂停菜单（用于退出） |
   | Game | `TogglePauseMenu()` |

4. `WhiteoutCharacter.cpp:171` 的 ESC 绑定目标从 `TogglePauseMenu` 改为调 HUD 的 `HandleBackRequested()`（保留 `bExecuteWhenPaused = true`）。游戏态下按键仍走游戏绑定，UI 态下走第 2 步的 widget 兜底，两条路汇到同一个函数。
5. 改造 `ToggleEvidence()`（`:1395`）：打开时依次 `HideActionPreview()` → 关对话（若开着）→ `SetLayer(Evidence)` → `SetShowMouseCursor(true)` → `FInputModeUIOnly`（`SetWidgetToFocus(EvidenceBorder->TakeWidget())`、`EMouseLockMode::DoNotLock`）；新增 `CloseEvidence()`：`bEvidenceVisible=false` → `SetLayer(Game)` → `SetShowMouseCursor(false)` → `SetInputMode(FInputModeGameOnly())`。E 键游戏绑定（`WhiteoutCharacter.cpp:419`）保持调用 `ToggleEvidence()` 不变。
6. 在 `ShowDialogueMenu/TogglePauseMenu/OpenSettings/CloseSettings/ResumeGame/ShowActionPreview/HideActionPreview` 各自末尾调用 `SetLayer(...)` 写入对应层，保证状态机唯一可信。
7. 角色移动/视角：Evidence 层用 UIOnly 后游戏输入自然失效，无需额外 `SetIgnoreMoveInput`；Dialogue 层沿用已有 `SetIgnoreMoveInput/LookInput(true)`。

**不做**：不改 Enhanced Input 的 MappingContext 结构；不给 ESC 绑新动作；不动规则。

**验收**：编译通过后按此 12 行路径表逐条手测并记录（截图或录屏）：
①游戏态 ESC→暂停 ②暂停 ESC→回游戏 ③暂停→设置→ESC→回暂停 ④设置再 ESC→回游戏（经暂停）⑤E 开证据板→鼠标可见、人物不转 ⑥ESC 关证据板→鼠标隐藏回游戏 ⑦证据板中按 E 也关闭 ⑧对话中 ESC→退出对话回游戏（不叠暂停菜单）⑨行动预览中 ESC→仅关预览 ⑩证据板中 ESC 不会叠出暂停菜单 ⑪结算屏 ESC→暂停菜单 ⑫开场播放中 ESC→跳过开场进暂停。
