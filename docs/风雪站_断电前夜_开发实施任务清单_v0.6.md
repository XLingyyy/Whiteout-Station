# 风雪站：断电前夜 — 开发实施任务清单 v0.6

日期：2026-07-26

依据：v0.5 发布版、v0.5 MVP 审计、用户本轮体验反馈、当前源码与规则审计、Unreal Engine 5.8 官方 UI/Input/Automation 文档，以及对阶段化对话与渐进式教学的公开研究。

## 一、版本目标

v0.6 将现有“可完整通关的功能型 MVP”推进为“新玩家能理解、选择有上下文、开场可读、体验可验证”的打磨版 Demo：

1. 对话意向按 NPC、证据、关系、人物需求和危机阶段逐步开放；没有具体语境时不显示“质疑”或“承诺”。
2. 顾衡的承诺条件分别绑定已发现的具体问题；叶澄不显示承诺入口；UI 隐藏与 C++ 规则拒绝使用同一套条件。
3. 开场改为全黑幕、中央白字、逐句淡入淡出；Space 或鼠标点击推进，最后从黑幕渐隐到第一人称站内视角。
4. HUD 增加动态“当前建议”，H 打开生存手册；目标、状态、信任、行动力和改变方式都有玩家可见解释。
5. 完善在线表达的多轮上下文、取消、等待与降级体验，同时维持 C++ 唯一规则权威。
6. 补齐真实输入路径、四结局、首局理解、时长和 AI A/B 的可复现验收。
7. 继续冻结顾衡与叶澄的人物模型、骨骼、材质、动作、动画、AnimBP 和 LookAt。

## 二、体验原则

- **渐进呈现**：只展示当前语境中有意义的意向和承诺条件；锁定内容不以灰色假按钮占位。
- **先教后考**：首次需要某个输入或状态概念时给出短提示；完整解释放在随时可查的生存手册中。
- **状态可行动**：每个状态说明必须同时回答“影响什么”和“怎样改变”。
- **剧情由玩家推进**：开场正文不自动跳句、不强制超时；输入负责推进，淡入淡出只负责节奏。
- **规则可追踪**：AI 不能开放意向、创建事实或修改状态；所有开放条件和结果都能由状态快照与事件日志复现。
- **不破坏既有工作**：主工作树中的地图、AnimeNPC、VRM4U、LookAt 和交互代码改动保持原样；v0.6 在独立工作树实施。

## 四、阶段化对话规则

### 顾衡

- 初始：显示“询问”；压力较高时显示“安抚”。
- 掌握发电机旁路疑点或烧毁继电器证据后：显示“质疑”。
- 至少进行过一次交谈，并发现可兑现的具体需求后：显示“承诺”。
- 承诺条件按上下文分别开放：
  - 伤情已明确且药品仍可保留：保留药品；
  - 伤情已明确且维修间尚未供暖：恢复维修间供暖；
  - 已掌握发电机责任线索并保留记录：保存完整维修记录。
- 已记录的同一承诺条件从列表移除。

### 叶澄

- 初始：显示“询问”。
- 她披露保温包后：可基于隐藏物资问题“质疑”。
- 危机发生或压力进入高位后：显示“安抚”。
- 不显示“承诺”；直接构造的 Promise 请求仍由 C++ 拒绝。

## 五、开场文本节拍

1. 昨夜，风暴切断了风雪站与外界的最后一条线路。
2. 清晨八点十五分，你在警报声和结霜的玻璃旁醒来。
3. 备用电池只能支撑到傍晚；顾衡负伤，叶澄守着所剩无几的医疗物资。
4. 要让救援听见这里，你必须修复发电机、校准室外天线，再发出求救信号。
5. 每项行动都会消耗时间，也会改变三个人的状态、信任与剩余物资。
6. 先看清现场，再决定该相信谁、把什么留到最后。
7. 风雪仍在敲打站体。你睁开了眼。

每次输入只推进一个节拍。输入发生在淡入阶段时先完成当前句显示，再次输入才进入淡出与下一句。

## 六、完成定义

以下条件全部成立才算 v0.6 Demo 完成：

1. V6-01 至 V6-11 全部 PASS；
2. 新局开场没有自动跳句，Space 与鼠标推进一致；
3. 初始对话不存在无语境承诺，UI 和规则层的开放条件一致；
4. 新玩家可在游戏内理解当前目标、状态影响和改变方式；
5. 三条成功路线、四类结局、在线/离线/失败降级均可复现；
6. 顾衡与叶澄冻结对象 OID 与 v0.6 基线一致；
7. Shipping 包绑定 clean source commit/tree，并通过发布校验；
8. 文档、提交和远端分支完成。
