# v1.5 人工确认后的语义与事务前提

用户已在任务中确认逐条审阅 120 条标注。原 Excel 保留 AI 辅助填写来源；本记录补充用户确认及本轮明确的行为要求，不覆盖原始标注。

## 执行前提

- 一条消息可以包含多个子意图，每项独立保留对象、话题、极性、引用、澄清和披露条件。消息只有一个事务 ID，成功提交最多占一轮，首个成功提交扣一次 AP。
- 明确的社交施压可以回应并按现有规则结算。缺少具体任务只追加局部追问，不执行维修、治疗等实体操作。纯澄清、未登记提议和不支持的承诺说明不扣 AP、不计成功轮数。
- NPC 已知与玩家已知分别建立夹具。NPC 私有知识仍须通过披露条件；玩家声称拥有证据不改变库存或知识。每个子意图以同一提交前快照评估权限，不能借同句另一问题预先解锁事实。实际披露成功提交后才更新玩家知识。
- 供暖地点支持控制室、维修间、医务室、厨房。时间使用当前日阶段的相对偏移解析后绑定绝对阶段，只允许尚未锁定的后续阶段。未说期限不默认为下一阶段，必须追问并展示明确阶段后再确认。老作者选项“下一阶段供暖维修间”保持其原有明确期限。
- 前提条件及多项条款完整保留。首轮实现可登记无附加前提的参数化供暖，以及现有保留记录／预留药品条件。任意条件判断、取得零件、治疗保证等尚不支持时明确告知、不登记、不转换成其他承诺。
- 保留记录／预留药品的现有规则以本日结束为期限，提议提示中明确展示；供暖不继承这一默认期限。修改提议只继承当前被引用版本中未修改的明确条款，不为初次缺失期限的提议补默认值。
- 解析最多 6 项，一条消息仍只有一次解析请求和一次合并表达请求。解析上限 1600 tokens，表达每项 640、整条最多 3840 tokens；超时仍为解析 3 秒、表达 7 秒。审计增加 message_schema_version=2 和 clause_results；原表达协议保持 v5。
- 确认绑定提议 ID 和版本；改期、换地点、添加条件均更新版本并重新确认。确认只在事务成功后消费，取消、验证失败和迟到回调不得消费。已登记相同条款不重复登记或奖励。
- 消息数、已提交轮数和提议 ID 分别记录。已提交两轮后纯提议不占第三轮；第三轮回答同时提出承诺后，只允许该提议的确认／取消收尾，不开放第四轮自由聊天。收尾不增加轮数或 AP，不重复登记。

## 验证顺序与报告

先用构造解析结果验证局部澄清、多意图、改期／换地点、失败恢复、取消、重复事务、重复确认、迟到回调、第三轮两种收尾路径。之后运行真实模型请求，分开报告语义理解、回应完整性、承诺生命周期、禁止副作用。模拟通过不计作真实模型通过；未支持条款的安全拒绝只计禁止副作用通过，不计完整玩法支持。
