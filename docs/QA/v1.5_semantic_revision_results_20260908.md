# v1.5 人工语义复核后的实现与验证结果

日期：2026-09-08。工作分支：main。首批实现提交：016d187；后续知识排序与确认恢复修正以本报告所在提交为准。

结论：消息事务、参数化承诺、版本确认及第三轮收尾已实现并完成定向验证。真实模型仍有字段偏差、解析失败及表达恢复，不标记为全部语义或完整玩法验收通过。原 120 条人工标注已归档，本轮真实测试覆盖下面的重点用例，未重新认证全部 120 条。

## 测试前提

- 每组重新开局并选择上午医务室供暖。生成器进度 0、药品 1、替代继电器 0、顾衡未治疗。所有子意图读取同一提交前快照；本句第一问披露的诊断不能提前授权第二问。
- 090 分三个前提：未诊断；通过正常作者选项提交取得诊断；取得诊断并完成独立安抚。最后一个实测提交前为诊断已知、叶澄信任 6.8、压力 4，满足替代方案披露条件。知识排序仅优先已通过可用性检查、明确询问且 NPC 已知的事实。
- 048 使用本次真实提交的 033 施压对话作为历史，验证连续施压及局部澄清；这与原工作表的文字历史不完全相同。
- 098–099 和第三轮混合消息均先在同一会话实际提交两轮作者对话。提议没有充当已提交轮数；其 ID、版本独立于消息计数。
- 供暖必须给出明确未来阶段，绑定绝对阶段和地点。缺少期限时追问。保留记录、预留药品沿用本日结束期限，并在确认提示中明示。
- 复杂条件、取得继电器、治疗保证暂不登记；整组复杂条款不被缩减为已支持的一项。不同未来阶段的多项供暖条款可以一起确认；同一阶段给不同地点供暖的冲突提议会被拒绝。

## 真实测试中发现并修复的问题

1. JSON 模式提示缺少 JSON 关键词导致 HTTP 400；证据片段类型未明确导致模型输出字符串。已修正提示格式，HTTP 日志保留状态码。
2. 修改地点时丢失原期限。待确认上下文增加当前阶段、绑定阶段及相对偏移，真实复测完成厨房／黄昏 v3 登记。
3. 取消被否定极性归一化抹除，模型也曾误把 reject_pending 填入 speech_act。分别修正解析处理与字段约束。
4. 发电机进度自由生成时编造检查过程。增加由当前状态生成的必需事实片段；仍保留自由文本质量的限制说明。
5. 第三轮确认的模型回复混入当前供暖地点，拒绝后无可用恢复。新增绑定提议的固定确认回复，正常事务完成后才显示登记条款。
6. 符合披露条件的保温包知识被同主题保留态度挤出。已授权、明确询问的已知事实优先于一般排序；真实复测和构造解析结果回归均覆盖。
