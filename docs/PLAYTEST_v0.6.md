# v0.6 试玩与体验验收

日期：2026-07-26

## 范围

本轮试玩聚焦用户提出的三个问题：对话意向缺少语境、进入游戏后不知道做什么、开场故事无法读完。同时检查状态解释、行动确认、路线代价、结果复盘、产品菜单和 AI 在线/离线体验。

验收由三类证据组成：

1. 1920×1080 / 1280×720 演示状态视觉基线；
2. 两条打包版真实鼠标/键盘路径及事件日志；
3. 10 项 Shipping 确定性路线与 AI A/B 矩阵。

## 首局体验

| 检查点 | 结果 |
|---|---:|
| 玩家能读完故事 | PASS：7 句没有自动超时，点击/Space 决定节奏 |
| 玩家知道核心目标 | PASS：开场第 4 句、HUD 当前建议和 H 手册重复呈现 |
| 玩家知道下一步 | PASS：动态建议会指向当前任务地点、对象和 F 双确认 |
| 玩家理解状态 | PASS：健/温/精/饱/稳/信任/AP 均解释影响、阈值和改变方式 |
| 玩家能查操作 | PASS：H 手册常驻可查，暂停菜单也可进入 |
| 玩家能安全试错 | PASS：行动先预览再提交，提前失败结算需要二次确认 |

故事阅读时间完全由玩家控制。淡入阶段的首次输入只补全当前句，再次输入才切换下一句，避免连按时漏读正文。

## 对话体验

- 顾衡初次交谈显示“询问、安抚”；叶澄初次交谈只显示“询问”。
- “质疑”只有在玩家掌握相关证据或叶澄披露隐藏物资后出现。
- “承诺”只有顾衡在已经交谈且存在可兑现具体需求时出现；已承诺条件会移除。
- 叶澄没有承诺入口，直接构造 Promise 也会被规则拒绝。
- 选定意向后仍可自由输入玩家说法；在线模型只润色回应，离线台词保留相同规则结果。

视觉目检确认隐藏项不会留下灰色空位，2 项与 4 项布局均重新排布，玩家可看到“当前可谈 N 项”和意向会影响的维度。

## 操作路径

真实输入路径 `survival_controls` 覆盖：

`点击开场 → Space 开场 → H → Esc → E → E → W → F 预览 → Q → F 提交 → Enter → Enter`

真实输入路径 `dialogue_free_text` 覆盖：

`点击开场 → Space 开场 → F 对话 → 点击询问 → 中文自由输入 → Enter → 点击离开 → Enter → Enter`

两条路径均由打包后的 Shipping 可执行文件运行，最终事件日志中的 action ID、AP、模型调用数、结局和屏幕状态与输入序列一致。

## 路线与复盘

结果页能区分：

- 医疗协作；
- 证据替代；
- 直接抢修；
- 强行自修。

复盘同时显示关键代价、承诺兑现、五项评分、三人最终状态、行动时间线和下一轮建议。`TaskSuccess`、`SurvivalWait`、`CostUncontrolled`、`TotalCollapse` 四类结局均有 Shipping 证据。

## 产品与可访问性

- 暂停菜单包含保存、读取、帮助、设置、重开和退出；
- 设置支持 FOV、四路音量、90%—120% 字号与减少动态效果；
- H/E/Esc 返回关系清楚，全屏面板会隐藏主 HUD 和准心；
- 结算前警告、AI 等待/取消/降级和行动提交均有可见反馈；
- 开场、教程、对话、暂停、设置和结果页在 1280×720 与 1920×1080 基线中无裁切。

## 已知边界

- 本轮没有外部玩家样本或统计性可用性研究；结论来自自动化、真实输入脚本和视觉审查。
- DeepSeek 为可选外部服务，连接质量与账户额度不受游戏控制；任何失败均回退本地台词。
- 顾衡与叶澄的人物模型及动作按用户要求冻结，角色外观与动作质量留待后续模型替换。
- Shipping 可执行文件未做商业代码签名，首次启动可能触发 Windows 的来源提示。

这些边界不阻断 v0.6 的离线完整流程、四结局或发布验收。
